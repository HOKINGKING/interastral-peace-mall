# 星际和平商城 · HTML 原型

对应 `docs/PRD.md` 的静态原型：**28 个页面**，点击可走通「浏览 → 加购 → 下单 → 支付 → 发货 → 收货 → 投诉」的主要路径。纯 HTML + CSS + 原生 JS，**不依赖任何 CDN 或构建工具**，离线双击即可看。

## 怎么看

直接双击 `index.html`（或用浏览器打开文件），右下角/页脚的「原型页面清单」可跳到全站索引 `sitemap.html`。

> 若浏览器对本地文件有限制，也可以在项目根目录起一个静态服务：
> `python -m http.server 8000` 然后访问 <http://localhost:8000/prototype/>

## 页面

**用户端（17）**：首页、分类页、商品列表、商品详情、登录、注册、个人中心、购物车、确认订单、模拟支付、订单列表、订单详情、收货地址、地址编辑、我的投诉与反馈、提交投诉、反馈详情。

**卖家后台（11）**：登录、工作台、分类管理、商品管理、SKU 管理、用户管理、订单管理、订单详情、投诉与反馈列表、投诉处理、操作日志。

## 可以点的交互

| 位置 | 行为 |
|---|---|
| 商品详情 | 切换规格 → 价格/库存/按钮状态联动；缺货规格点击会提示 |
| 购物车 | 加减数量、勾选/全选 → 小计与合计实时重算 |
| 支付页 | 30 分钟倒计时；两个按钮各自提示结果 |
| 各表单 | 提交被拦截，只弹提示，不写任何数据 |
| 删除/禁用等危险操作 | 弹提示，模拟「二次确认」与状态机拒绝 |
| 投诉页 | 订单卡片为只读快照，类型可切「普通反馈」 |

所有按钮点击都只弹提示条，**不会真的发请求、也不会改文件**——原型只用于确认信息层级与交互路径。

## 改数据 / 重新生成

页面由 `_build.mjs` 生成，数据（商品、订单、投诉）写在脚本顶部的 `PRODUCTS` / `ORDERS` / `FEEDBACKS` 里：

```bash
node prototype/_build.mjs
```

改完重新生成即可，不要直接改 28 个 HTML（会被覆盖）。样式在 `assets/style.css`，交互在 `assets/app.js`，两者与生成逻辑无关，改完刷新页面就生效。

## 视觉设定

整体取《崩坏：星穹铁道》里**星际和平公司（IPC）**的企业视觉语言：深空藏蓝底 + 烫金点缀 + 六边形币章 + 星轨元素。

| 元素 | 位置 | 说明 |
|---|---|---|
| 官方标识 | 页头、页脚、后台侧栏用**白色版**；后台登录卡（白底）用**黑色版**；首页 hero 右侧做低透明度水印 | `assets/ipc-logo-light.png`、`assets/ipc-logo-dark.png`，由项目成员提供 |
| 企业信息条 | 页头最上方一条细金带 | 「星际和平公司 · 传统项目部 / 以信用点（Credit）结算」 |
| 认证印记 | 商品详情标题右侧 | 「IPC 认证正品」小金印，强调官方直营 |
| 配色 | 全局 | 金色 `#e7c873` 只用于「品牌层」（分隔线、印记、高亮），交互色仍是靛蓝，避免两套颜色抢注意力 |
| 兜底徽记 | 标识图片加载失败时 | `assets/emblem.svg` 与 `_build.mjs` 里的 `emblem()`，保证不会出现裂图 |

## 与真实实现的边界

- 不含后端、不含数据库，所有列表数据是脚本里的示例；
- 登录态是写死的「你好，星野」，没有真实的会话与拦截器；
- 权限、库存并发、状态机校验都在 PRD 里，原型只体现「界面长什么样、点了会怎样」；
- 图片用渐变 + emoji 占位，避免外链失效。
